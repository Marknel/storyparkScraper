# Implementation Plan: Home Assistant MQTT Discovery & Alerting Integration

**Branch**: `002-home-assistant-mqtt` | **Date**: 2026-09-09 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-home-assistant-mqtt/spec.md`

## Summary

Integrate Storypark Scraper with Home Assistant via standard MQTT Discovery protocol. The scraper will automatically publish device and entity discovery schemas and broadcast synchronized status telemetry (operational state, last run duration, cumulative stories/photos, and a dedicated `problem` alert binary sensor) to an MQTT broker.

## Technical Context

**Language/Version**: Python 3.11+ (running on Python 3.14 on Windows and Python 3.12 in CI)

**Primary Dependencies**: `paho-mqtt>=2.0.0`

**Storage**: Reads existing `status.json` and SQLite `state.sqlite`; no new storage engine required.

**Testing**: Standard Python `unittest` with mock MQTT client tests.

**Target Platform**: Windows 10/11 / Windows Server (Production VM), Linux / Docker

**Project Type**: CLI tool and scheduled background daemon

**Performance Goals**: Publish discovery and telemetry in < 200ms; zero impact on core scraping throughput.

**Constraints**: Network failures or broker unreachability MUST NEVER interrupt or abort primary Storypark scraping operations.

**Scale/Scope**: Small footprint; 1 device, ~10 MQTT entities in Home Assistant.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [x] **Library-First**: MQTT publisher designed as an independent, self-contained module (`storypark_scraper/mqtt.py`).
- [x] **CLI Interface**: Exposes direct testing command `python -m storypark_scraper mqtt-publish`.
- [x] **Test-First**: Unit tests for schema validation, topic construction, telemetry formatting, and connection failure handling.
- [x] **Integration Safety**: Graceful fallback on network/broker drops without impacting scraping pipeline.
